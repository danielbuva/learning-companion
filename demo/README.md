# Synthetic demonstration

Choose **Try a synthetic lesson**. It creates an authored shortest-path guide, four initially unassessed skills, a directed weighted graph, a session, a review, and a manageable plan. It creates no learner profile or assessed success.

1. Continue the graph. Select C and give a reason; submit. The server checks the current state, records assistance, settles C, and relaxes its outgoing edges. The reasoning still needs tutor inspection.
2. Pause and save. In another authorized chat, request `learning_read` with `{"action":"resume","id":"demo-session"}`. Compare graph, distances, backpointers, response, hints, and unresolved action.
3. Reveal help and answer again. It must remain assisted, including after a branch or replay.
4. Create a code workspace; predict, run the isolated JavaScript, inspect actual output, and save the draft. Execution is distinct from learning evidence.
5. Inspect a source line, save a personal annotation, and attach exact versioned context on a supported host.
6. Ask the tutor to grade, correct, invalidate, or plan follow-up through `learning_write`. History shows learner versus tutor contributions.

These demonstration instructions are not evidence that every host interaction has already passed. See the verification matrix.
